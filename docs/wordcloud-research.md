# Publium 워드클라우드 도입 조사

## 결론

- 문서 원본은 **Obsidian 호환 Markdown**으로 프로젝트 `docs`에 둔다.
- 기능명은 `워드클라우드`보다 **연구 키워드 지도**가 목적을 잘 설명한다.
- 첫 버전은 사용자가 수집한 논문의 **제목과 초록**에서 핵심어를 추출한다.
- **포함 논문 수를 중심으로 총 등장 횟수와 제목 가중치를 보조 반영**한다.
- 단어를 누르면 논문 목록을 해당 단어로 필터링한다.
- 화면 배치는 `d3-cloud`로 계산하고 React에서 SVG로 그리는 방식을 추천한다.
- 정확한 비교가 필요하므로 워드클라우드 옆에 상위 키워드와 논문 수 목록을 함께 제공한다.

## 2026-08-25 구현 상태

- 검색 결과: 현재 검색한 최대 100편을 브라우저에서 즉시 분석
- 관심 논문: `GET /api/wordcloud`가 사용자의 전체 활성 관심 논문을 서버에서 분석
- 프로젝트·미분류·연도·저널·검색 조건 지원
- 상위 키워드에 `포함 논문 수 · 총 등장 횟수` 표시
- 원문·임베딩·OpenAI API 미사용
- 사용자 범위와 `is_del = false` 조건을 테스트로 고정
- 서버 테스트 51개, 프론트 빌드, 1440px·390px 자동 화면 점검 통과

## 왜 도입하는가

Publium에는 사용자가 수집한 논문의 제목과 초록이 이미 저장된다. 현재 개요 화면은 논문 수, 연도별 추이, 상위 저널을 보여주지만 **무슨 주제의 논문을 모았는지**는 바로 보여주지 않는다.

워드클라우드는 다음 질문에 빠르게 답하는 보조 탐색 도구다.

- 내 논문 컬렉션에서 반복되는 연구 주제는 무엇인가?
- 특정 질환·치료법·바이오마커가 포함된 논문은 어떤 것인가?
- 새 논문을 수집한 뒤 관심 주제의 분포가 어떻게 달라졌는가?

PubMed 자료를 대상으로 한 DELVE 연구도 워드클라우드를 단어·구문의 빈도 요약과 문서 필터 진입점으로 사용했다. 다만 맥락과 관계를 설명하는 도구는 아니라고 구분한다. [DELVE 논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC5543346/)

## 제품 정의

### 기본 화면

- 위치: `검색 결과` 상단과 `관심 논문` 연구 도구 영역
- 제목: `연구 키워드 지도`
- 범위: 로그인 사용자의 삭제되지 않은 수집 논문 전체
- 표시: 상위 30~40개 단어 또는 구문
- 방향: 가로 중심이며 일부 짧은 단어만 90° 회전
- 상호작용: 단어 클릭 → `논문 목록` 탭 → 해당 키워드 검색
- 보조 정보: 마우스 오버·포커스 시 `포함 논문 N편` 표시
- 빈 상태: `논문을 수집하면 주요 연구 키워드가 표시됩니다.`

### 두 번째 단계

- 최근 검색 결과 / 전체 컬렉션 범위 전환
- 출판 연도 범위 필터
- 제목만 / 제목+초록 전환
- 2개 기간의 키워드 변화 비교
- MeSH 범주에 따른 의미별 색상·영역 구분

일반적인 무작위 배치보다 의미적으로 구분된 영역이 주제 이해에 더 효과적이라는 사용자 연구가 있다. 의미 그룹을 제공할 수 있게 된 뒤에만 색상과 위치에 의미를 부여한다. [의미 그룹 워드클라우드 평가](https://pubmed.ncbi.nlm.nih.gov/30872231/)

## 데이터와 점수

### 1차 데이터

1. 제목
2. 초록
3. 수집 검색어

검색어는 사용자의 의도를 보여주지만 반복 수집에 따라 편향될 수 있다. 첫 화면의 단어 크기는 제목·초록을 기준으로 계산하고 검색어는 별도 정보로만 제공한다.

### 추천 점수

한 논문 안에서 같은 단어가 여러 번 나와도 `paper_count`는 한 번만 올린다.
대신 실제 반복은 `occurrences`에 모두 기록해 약한 로그 가중치로 반영한다.

```text
paper_count(term) = 해당 term이 한 번 이상 등장한 활성 논문 수
occurrences(term) = 제목+초록에서 term이 등장한 총횟수
score(term) = paper_count + 0.35 × title_count + 0.55 × log(1 + occurrences)
```

- 화면의 글자 크기: `score`
- 툴팁과 목록의 숫자: `paper_count`와 `occurrences`
- 이유: 긴 초록이나 반복 표현 하나가 전체 결과를 지배하는 문제를 줄인다.
- 최소 조건: 2편 이상에서 등장한 용어
- 표시 개수: 데스크톱 40개, 모바일 25개

### 전처리

- Unicode 정규화와 소문자 변환
- HTML, 구두점, 단독 숫자 제거
- 영어 기본 불용어 제거
- `study`, `result`, `method`, `patient`, `conclusion`, `background` 등 논문 구조상 반복되는 일반어 제거
- 단수·복수와 하이픈 표기 통합
- 의미 있는 2단어 구문 우선 유지: `machine learning`, `breast cancer`, `risk factor`
- 너무 짧은 토큰과 PMID·DOI 형태 제거
- 제외어 목록은 코드와 테스트로 관리

단순 빈도는 `using`, `used`, `data`처럼 내용과 관계가 약한 단어를 상위에 올릴 수 있으므로 전처리가 결과 품질을 좌우한다. [연구 논문 컬렉션 시각화 사례](https://pmc.ncbi.nlm.nih.gov/articles/PMC7515106/)

### MeSH 확장

장기적으로는 자유 텍스트보다 **MeSH 우선** 방식을 권장한다. MeSH는 NLM이 관리하는 생의학 분야의 계층형 통제 어휘라서 동의어와 표기 차이로 인한 분산을 줄일 수 있다. [NLM MeSH 소개](https://www.nlm.nih.gov/mesh/meshhome.html)

현재 Publium은 PubMed XML에서 제목과 초록 중심으로 저장한다. 이후 EFetch XML 파서를 확장해 MeSH·저자 키워드를 함께 저장할 수 있다. NCBI는 PubMed 레코드를 XML로 가져오는 EFetch 방식을 공식 제공한다. [NCBI E-utilities 문서](https://www.ncbi.nlm.nih.gov/books/NBK25499/)

추천 우선순위는 다음과 같다.

1. MeSH 주요 주제
2. 저자 키워드
3. 제목·초록에서 추출한 구문

MeSH가 아직 배정되지 않은 최신 논문도 있으므로 제목·초록 fallback은 유지한다.

## 시각화 원칙

- 워드클라우드는 **개요와 탐색용**이며 정확한 순위표를 대체하지 않는다.
- 색상은 장식과 데이터 의미를 혼용하지 않는다.
- 가장 큰 단어와 가장 작은 단어의 크기 차이를 과도하게 벌리지 않는다.
- 배치 난수에 고정 seed를 사용해 같은 데이터는 같은 배치로 표시한다.
- 단어를 회전시키지 않는다.
- 키보드 포커스, 클릭, 툴팁을 지원한다.
- 스크린 리더를 위해 동일 데이터를 순위 목록으로 제공한다.
- 상위 10개는 막대 또는 숫자 목록을 병기한다.

워드클라우드는 글자 크기로 빈도를 표현하지만 정밀한 값 비교와 시간 변화 비교에는 불리하다. 시간 추세가 핵심이면 선·막대 그래프가 필요하며, 연구에서도 여러 일반 워드클라우드만으로 추세를 비교하는 것은 인지 부담이 크다고 설명한다. [SparkClouds 연구](https://pubmed.ncbi.nlm.nih.gov/20975157/)

## 구현 방식 비교

| 선택지 | 장점 | 단점 | 판단 |
|---|---|---|---|
| `d3-cloud` + React SVG | 위치 계산과 화면 렌더링을 분리할 수 있음. 클릭·포커스·툴팁 구현이 쉬움. 현재 D3 기반 그래프 코드와 방향이 같음 | 전처리와 React 래퍼는 직접 작성해야 함 | **추천** |
| `wordcloud2.js` Canvas | 의존성이 없고 빠르게 그릴 수 있음 | Canvas의 접근성·개별 단어 상호작용·반응형 제어가 더 번거로움 | 간단한 이미지형 기능에 적합 |
| Python `wordcloud` | 마스크와 PNG 생성에 강함 | 현재 Node 중심 운영 경로에 별도 Python 서비스가 필요함. 브라우저 상호작용이 약함 | 보고서 이미지 내보내기 때 검토 |
| 직접 SVG 배치 | 완전한 제어 | 충돌 회피와 반응형 배치 구현 비용이 큼 | 비추천 |

`d3-cloud`는 Canvas의 문자 마스크로 배치를 계산하고 결과 위치를 이벤트로 돌려준다. 이 좌표를 React SVG 요소로 그리면 개별 단어를 버튼처럼 다룰 수 있다. [d3-cloud 공식 저장소](https://github.com/jasondavies/d3-cloud), [npm 패키지](https://www.npmjs.com/package/d3-cloud)

대안인 `wordcloud2.js`는 Canvas 또는 HTML에 `[단어, 크기]` 목록을 그린다. [wordcloud2.js 공식 저장소](https://github.com/timdream/wordcloud2.js/)

Python `wordcloud`는 정적 이미지, 임의 마스크, 색상 함수가 필요할 때 유리하지만 `numpy`, Pillow, matplotlib 의존성이 추가된다. [Python word_cloud 공식 저장소](https://github.com/amueller/word_cloud)

## Publium 구현안

### 서버

`GET /api/wordcloud`를 구현했다.

현재 `/api/papers`는 한 번에 최대 100편만 클라이언트로 보내므로 브라우저에서 현재 목록만 집계하면 전체 컬렉션을 잘못 요약할 수 있다. 서버가 활성 컬렉션 전체를 사용자 범위 안에서 집계해야 한다.

```json
{
  "scope": "collection",
  "paperCount": 148,
  "terms": [
    { "text": "machine learning", "score": 42, "paperCount": 31 },
    { "text": "biomarker", "score": 35, "paperCount": 28 }
  ]
}
```

- 인증된 `user_id`로 범위를 제한한다.
- `user_paper_collections.is_del = false`를 반드시 적용한다.
- 공유 논문 레코드의 제목·초록을 읽어 사용자 컬렉션 안에서만 집계한다.
- 결과 정렬은 `score DESC, text ASC`로 고정한다.
- 입력 데이터가 같으면 결과가 같도록 전처리를 순수 함수로 분리한다.
- 파생 결과는 DB에 저장하지 않고 요청 시 계산한다.
- 프로젝트·미분류와 목록 검색 조건을 동일하게 적용한다.
- 화면용 `/api/papers`의 100편 제한과 분리해 전체 활성 범위를 집계한다.

### 클라이언트

`Dashboard.jsx`의 개요 데이터와 함께 워드클라우드를 불러온다.

```text
Overview
├─ 지표 카드
├─ 연도별 추이 / 상위 저널
└─ 연구 키워드 지도
   ├─ WordCloud SVG
   └─ 상위 키워드 목록
```

- `WordCloud.jsx`: 레이아웃과 상호작용
- `wordcloud.js`: 점수 변환, 고정 난수, 크기 계산
- 단어 클릭 시 기존 `/api/papers?keyword=...` 검색을 재사용한다.
- 컨테이너 크기 변경 시 다시 배치하되 debounce한다.
- 레이아웃 계산 중에는 이전 결과 또는 skeleton을 유지한다.

## 데이터베이스 정책

MVP에는 새 테이블이 필요 없다. 추후 사용자별 제외어, 저장된 워드클라우드, 스냅샷을 DB에 보관한다면 다음을 적용한다.

- `is_del boolean not null default false`
- `deleted_at`, `deleted_by`, `delete_reason`
- 모든 일반 조회·집계에 `is_del = false`
- 삭제는 `UPDATE`로 처리하고 복구 경로 제공
- 사용자 설정과 결과는 인증된 `user_id`로 제한

## 테스트 기준

- 다른 사용자의 논문이 키워드 점수에 포함되지 않는다.
- 소프트 삭제된 컬렉션 논문이 제외된다.
- 동일 논문에서 반복된 단어는 `paperCount`를 한 번만 올린다.
- 제목 가중치와 동률 정렬이 항상 동일하다.
- 불용어, 숫자, PMID·DOI가 제외된다.
- 빈 초록과 빈 컬렉션을 안전하게 처리한다.
- 단어 클릭이 해당 사용자의 논문 목록 필터로 연결된다.
- 키보드만으로 단어와 상위 목록을 탐색할 수 있다.
- 모바일에서 단어가 잘리거나 화면을 가로로 넘기지 않는다.
